## 1. Executive Summary

A thorough security audit was conducted covering all procedural generation systems, authoring CLI tools, template neutrality mechanisms, and the newly generated 18-case content pack. All systems were evaluated against the security specifications in `PROMPTS.md` R3 and `SYSTEM_DESIGN.md` (§3.6, §4.3, §8, §12).

### Key Audit Highlights:
1. **Answer & Secret Redaction (Procedural Content Pack)**:
   - Deep-scans of `toPublicCase` across all 18 generated cases verified complete stripping of the 8 forbidden engine keys: `truth`, `claims`, `culpritIds`, `asserts`, `keyEvidence`, `liars`, `seed`, `conspiracyHooks`.
   - All locked clues omit both `text` and `asserts`, exposing only `{ id: "locked_<n>", type, locked: true, hint }`.
2. **Presentation Fair-Play & Leak Elimination**:
   - Automated leak scan verified that zero character first or last names appear in any generated case title.
   - Case briefings list all active suspects in randomized order, eliminating culprit single-out giveaways.
   - V16 validator check enforced across all authored and generated cases with 100% compliance.
3. **CLI Sandboxing & Path Traversal Prevention**:
   - `lastlie generate`, `lastlie render`, and `lastlie validate` enforce strict path boundaries via `assertSafePath`. Traversal attempts (e.g. `../../etc`) throw `SecurityError` and terminate execution.
4. **Pure Determinism & Cryptographic Independence**:
   - PRNG (`mulberry32`) and fingerprinting (`cyrb128`) are implemented without Node.js `crypto` or platform-specific APIs. They remain 100% deterministic and portable across web, mobile, and server.

## 3. Detailed Audit by Dimension (PROMPTS.md R3)

### A. Answer Leakage
- **Scope**: 18 procedural cases in `packages/content/cases/generated/`.
- **Method**: Automated deep-scan (`tests/security_audit_p3.test.ts`) traversing the complete object tree of each generated case.
- **Results**: Zero leaks detected. Public payloads strictly adhere to `CasePublic` allow-lists.

### B. Input Validation & Sandboxing
- **CLI Commands**:
  - `lastlie generate --out <dir>`: Validates that resolved output directory and individual case files cannot escape the repository root.
  - `lastlie validate <glob>`: Globs are normalized and restricted to safe repository paths.
- **Zod Schema Enforcements**: Every case generated by CLI must pass `CaseDefinitionSchema.parse()` and `validateCase()` with zero errors before being written to disk.

### C. Fingerprinting & Deduplication
- **Deterministic Hash**: `fingerprint(def)` extracts:
  - normalized template ID,
  - culprit roles (role-based, not name-based),
  - decisive contradiction rule ID (via ground truth reveal beats),
  - sorted location IDs,
  - liar count,
  - sorted key evidence clue types.
- **Collision Resistance**: Permuting character names produces identical fingerprints; altering culprit roles or key contradiction rules alters the fingerprint.

### D. Secrets & Configuration
- **Gitleaks Scan**: Configured in `.github/workflows/ci.yml`. Git history scanned for private keys, AWS/Supabase credentials, and JWT secrets.
- **Environment Separation**: No `.env` secrets committed. Service-role tokens documented exclusively for Phase 4 Supabase deployments in `docs/deploy.md`.

### E. Dependencies (pnpm audit)
- Evaluated `pnpm audit --audit-level=critical`.
- Vulnerabilities detected in nested dev tools (`tar` via `@expo/cli` and `tinypool` via `vitest`). Neither package is bundled or executed in production client or backend runtime. Documented in Human Action list.
