# WP-54 — Push Notifications & Reminders Report

## 1. Summary
- **Expo Notifications Integration**: Added `expo-notifications@~0.29.14` (committed in separate `[WP-54] deps:` commit) and configured foreground notification handling and scheduled triggers.
- **Opt-In Privacy Protection**: Implemented strict opt-in gating (`shouldPromptForPush` in `apps/mobile/src/features/notifications/service.ts`). The application **NEVER** prompts for notification permissions on first launch. The prompt appears only after the player has completed their 2nd investigation (`solvedCasesCount >= 2`) and has neither opted in nor dismissed the prompt.
- **Daily Local Time Reminders**: Scheduled local morning dispatches (`09:00` local time) using `Notifications.scheduleNotificationAsync()` with `SchedulableTriggerInputTypes.DAILY`.
- **Zero-Spoiler Template Guarantee**: Defined `DAILY_DISPATCH_TEMPLATES` in `apps/mobile/src/features/notifications/types.ts`. All notification text is audited and verified via `deepScan` to ensure zero exposure of culprit names, liar flags, clue assertions, or puzzle solutions.
- **Backend Token Synchronization with RLS**: `syncPushTokenWithBackend()` syncs tokens via `POST /push/token` (`@lastlie/api-contract`) and/or directly with Postgres `public.push_tokens` table governed by Row Level Security (`auth.uid() = user_id`).
- **One-Tap Opt-Out in Profile**: Added a dedicated "Daily Dispatch Alerts" toggle switch (`testID="profile.notifications.toggle"`) in `apps/mobile/src/features/profile/ProfileFeature.tsx`. Toggling off immediately cancels all scheduled notifications (`cancelAllScheduledNotificationsAsync()`) and deletes the token from remote storage.

## 5. Decisions Made
1. **Case-Count Gating**: Filtered session store submitted/awarded sessions to compute unique solved case count. The prompt triggers only when `solvedCasesCount >= 2` and `!hasPromptedForPush`, ensuring a seamless first-time user experience without premature permission dialogs.
2. **Local Storage First with RLS Cloud Sync**: Notification preferences and tokens are saved in local storage (`getStorage()`) so local/offline play remains fully supported, while authenticated remote sessions automatically sync tokens to `public.push_tokens` via Supabase RLS.
3. **Graceful Degraded Mode**: If running in an emulator, web browser, or without an active Expo project ID, push token retrieval falls back to a simulated local identifier, allowing full functional testing of scheduling and opt-out workflows without crashes.
