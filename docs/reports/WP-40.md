## 1. Summary
- **Supabase Project Initialization**: Configured `supabase/config.toml` for project `the-last-lie` with local port assignments and standard extensions.
- **Relational Schema (SYSTEM_DESIGN §8.1)**: Built migration `20261101000000_schema_and_rls.sql` covering all 9 non-† core tables (`profiles`, `cases`, `case_private`, `case_sessions`, `case_results`, `player_progress`, `player_unlocks`, `daily_cases`, `game_config`) with foreign keys, cascading deletes, `CHECK` constraints on status/difficulty, and optimized B-tree indexes.
- **Strict Row Level Security (RLS)**: Enabled RLS across all 9 tables. Policies strictly match §8.1:
  - `cases`: SELECT where `status = 'published'` for `anon` and `authenticated`.
  - `case_private`: Zero client policies (absolute default deny for `anon` and `authenticated`).
  - `case_sessions`, `case_results`, `player_progress`, `player_unlocks`: Authenticated users can SELECT only their own rows (`user_id = (select auth.uid())`).
  - `profiles`: Authenticated users can SELECT and UPDATE only their own row.
  - `daily_cases`, `game_config`: Global read-only for `anon` and `authenticated`.
- **Revoked Client Mutations**: Revoked direct `INSERT`, `UPDATE`, and `DELETE` on all gameplay tables (`cases`, `case_private`, `case_sessions`, `case_results`, `player_progress`, `player_unlocks`, `daily_cases`, `game_config`) from `anon` and `authenticated`. All gameplay state changes must flow through Edge Functions executing as `service_role`.
- **Auth Trigger**: Created `handle_new_user()` security-definer trigger function on `auth.users` that automatically provisions `public.profiles` and `public.player_progress` on signup.
- **Deterministic Seed Pipeline**: Created `supabase/scripts/generate_seed.ts` that compiles `game_config` defaults and uses `toPublicCase` to publish `case_0001` through `case_0004` into `cases` (public payload) and `case_private` (full definition), plus a daily case entry.
- **pgTAP Test Suite**: Created `supabase/tests/01_rls_security.sql` asserting 12 security test cases covering `case_private` lockdown, draft case invisibility, session isolation, write revocations, and signup trigger execution.
- **Offline Syntax Validation**: All SQL files validated offline against the PostgreSQL grammar using `sql-formatter -l postgresql`.
