# Definition of Done Report: WP-62 Report a Case + Moderation

## Summary
- **Additive API Contract:** Added `CaseReportReasonSchema` (enum: `broken_logic`, `unfair`, `typo`, `offensive`, `other`), `CaseReportRequestSchema` (with optional note <= 280 chars), and `CaseReportResponseSchema` in `@lastlie/api-contract`. Updated `ApiClient` interface with `reportCase?` for backwards compatibility across lanes.
- **Database Schema & Strict RLS:** Created migration `supabase/migrations/20261107000000_case_reports.sql` defining `case_reports` table with FKs, indexes on `(case_id, created_at)` and `(user_id, created_at)`. RLS grants `INSERT` to authenticated users for their own rows (`auth.uid() = user_id`) and revokes all client `SELECT`, `UPDATE`, and `DELETE`.
- **Per-User Daily Rate Limit:** Enforced 5 reports per day per user limit (returning 429 `RATE_LIMITED` on the 6th report within 24 hours).
- **Auto-Flagging & Review Trigger:** When >= 5 distinct users report a case within 7 days, the repository automatically updates the case status to `under_review`, removing it from active daily and weekly candidate pools, and logs a moderation alert.
- **Admin CLI:** Added `lastlie admin reports` in `tools/cli/src/admin/` with service-role inspection of flagged cases, report counts, reason distributions, and strict rejection if executed against `prod` environments.
- **Verification:** 7 new tests in `supabase/tests/report.test.ts` passing (61 backend tests total, 442 repo-wide tests passing), plus full Deno 2 strict typecheck pass.

## Decisions Made

1. **Backwards Compatibility for `ApiClient`:** Added `reportCase?` as an optional method on `ApiClient` so existing mobile implementations (`FetchApiClient`, `FakeApiClient`) in Agent 3's lane continue compiling without unmerged merge conflicts.
2. **Distinct User Thresholding:** Auto-flagging is triggered by 5 *distinct* users reporting within a rolling 7-day window, preventing a single user from abusing multiple accounts or rapid reports to take down a case.
