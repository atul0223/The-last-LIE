## 1. Summary

- Authored migration `supabase/migrations/20261105000000_daily_weekly.sql`:
  - Tightened `daily_cases` RLS so clients can read only current or past dates (`date <= current_date`); future dates cannot be read via client queries.
  - Implemented `fill_daily_cases_ahead(p_days_ahead)` stored procedure (and TypeScript counterpart `fillDailyCasesAhead`) ensuring 14-day advance coverage without case reuse within 90 days.
  - Created `weekly_cases` table (open/close window, RLS preventing reads before window opens).
  - Created `weekly_attempts` table (`primary key (weekly_id, user_id)` ensuring only the first attempt counts for leaderboard ranking).
- Implemented routes:
  - `GET /daily`: Public route strictly returning today's UTC case.
  - `GET /weekly`: Public route returning the active weekly case and open status.
  - `GET /weekly/:id/aggregate`: Server-enforced secrecy; returns 403 `WEEKLY_NOT_CLOSED` while the window is open, and full anonymous aggregate statistics and leaderboard once the window closes.
- Anti-Cheat & Fair Play:
  - Fastest solve sanity: attempts flagged `too_fast` are excluded from the competitive leaderboard.
  - Replays/subsequent attempts are recorded for personal history but excluded from competitive leaderboard rankings.
- Tested and verified in `supabase/tests/daily_weekly.test.ts`.
