## 1. Summary

- Implemented `POST /sessions/:id/submit` with server-authoritative scoring (`scoreSubmission`), reveal generation (`buildReveal`), and progression calculation (`applyResult`).
- Concurrency & Idempotency: Implemented atomic submit execution via `saveSubmitTransaction` and created the PostgreSQL stored procedure `submit_case_session` (`supabase/migrations/20261102000000_submit_rpc.sql`). Concurrent calls (e.g. `Promise.all`) result in exactly one row in `case_results` and identical returned payloads.
- Replay Scoring: Replay sessions (`mode: 'replay'`) correctly scale progression XP by the `0.25x` multiplier.
- Timing Sanity: If elapsed time (`submittedAt - startedAt`) is below `minSubmitDurationSeconds` (15s), the `too_fast` flag is recorded on the result without rejecting the submission.
- Authoring CLI Publish: Implemented `lastlie publish <glob> --env local|staging|prod [--dry-run] [--yes]` in `tools/cli/src/publish/`. Refuses on any validator errors, generates `toPublicCase` public payload, stores private definition, automatically bumps versions when content changes, and enforces production confirmation.
