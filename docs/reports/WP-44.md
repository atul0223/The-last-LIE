# WP-44 Definition of Done Report — Auth & Profiles

## Summary
- **Supabase Client with Graceful Fallback**: Implemented Supabase client initialization in `apps/mobile/src/lib/supabase/client.ts`. When `EXPO_PUBLIC_SUPABASE_URL` or `EXPO_PUBLIC_SUPABASE_ANON_KEY` are missing or empty, `isAuthEnabled()` returns `false`, preventing client crashes and gracefully keeping the app in local mode.
- **Chunked Expo SecureStore Session Adapter**: Implemented `createChunkedSecureStorage` (`apps/mobile/src/lib/supabase/secureStorage.ts`) conforming to Supabase `SupportedStorage`. Android SecureStore throws when values exceed 2048 bytes; our chunking adapter splits tokens at 2,000 characters across `${key}_chunk_${i}` with a `${key}_chunk_meta` header, reassembles them on read, cleanly removes all chunks on delete, and gracefully falls back to an in-memory store in unit test / web environments.
- **Anonymous Sign-In & Email OTP Upgrade**: Implemented `AuthService` (`apps/mobile/src/lib/supabase/authService.ts`). On first launch, the app initiates an anonymous guest session. When upgrading via `sendEmailOtp` and `verifyEmailOtp`, Supabase Auth links the email to the existing user, preserving the exact same `user.id` so local progress is seamlessly attached to the permanent account.
- **Feature-Flagged Social Auth**: Created `SocialAuthButtons.tsx` with Apple and Google sign-in options, strictly disabled behind feature flags (`EXPO_PUBLIC_ENABLE_APPLE_AUTH` and `EXPO_PUBLIC_ENABLE_GOOGLE_AUTH`). Buttons display only when explicitly enabled by credentials.
- **Profile Dossier & Customization**: Built `ProfileFeature.tsx` and `useProfile.ts` in `apps/mobile/src/features/profile/`. Supports validated display name editing (2–30 alphanumeric chars, hyphens, spaces, underscores), detective rank selection from earned titles, and persistent privacy toggles (`publicProfile`, `shareAnalytics`, `leaderboardVisible`) stored in local `KeyValueStore`.
- **Anti-Cheat Local Progress Migration**: Implemented `POST /account/migrate-local` integration (`migrateLocalProgress`). Local P2 solved cases are transmitted with case IDs and completion timestamps only. The client never supplies scores or XP, preventing client-side score injection.
- **Account Deletion & Data Clearing**: Integrated `DELETE /account` (`deleteAccount`). On user confirmation, calls backend account purge, signs out from Supabase, and clears the local session store.
- **Accessibility & Test IDs**: All interactive elements provide accessible roles and labels (`accessibilityRole="button"`, `accessibilityLabel`), with consistent testIDs following `<feature>.<element>[.<id>]` conventions (e.g. `profile.button.upgrade`, `profile.input.display_name`).
- **Security & Zero Leaks**: Validated with `deepScan` tests in `tests/auth_profile.test.tsx` to ensure no sensitive internal game keys (`truth`, `claims`, `culpritIds`, `seed`, `keyEvidence`, `liars`) or credentials leak to profile state or network payloads.

## Decisions Made

1. **Chunk Threshold at 2,000 Chars**: Android's `expo-secure-store` throws an exception for values exceeding 2048 bytes. Splitting at 2,000 characters provides safety headroom for multi-byte UTF-8 sequences while minimizing SecureStore read/write operations.
2. **Metadata Key Tracking (`_chunk_meta`)**: A single JSON metadata entry tracks chunk count, ensuring clean iteration during reads and preventing dangling orphaned chunks if a subsequent token has fewer chunks than a previous one.
3. **Anti-Cheat Migration Guard**: `migrateLocalProgress` strictly constructs `MigrateLocalRequest` extracting only `caseId` and `submittedAt`. Server-side validation decides what historical cases to unlock; no unverified client scores or XP can be submitted.
4. **Graceful Degradation to Guest Dossier**: When Supabase credentials are not provided (e.g. offline dev or unconfigured test builds), the app remains fully functional in local mode, treating the user as a local field operative with full access to local profile customization and offline cases.
