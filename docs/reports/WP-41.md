## 1. Summary

- Built the core backend API as a portable Hono application in `supabase/functions/api/app.ts` driven by dependency injection: `{ repo, auth, clock, rateLimiter, config }`.
- Implemented global middlewares: `x-request-id` header generator, CORS allow-list from configuration, 64KB request body limit, sliding-window per-user/IP rate limiting (60/min), and an error handler that suppresses stack traces.
- Implemented core routes:
  - `POST /sessions`: Starts session with default unlocked clues; returns `{ session, case }`.
  - `POST /sessions/:id/unlock`: Evaluates unlock conditions with engine `canUnlock`; handles placeholder ids (`locked_<n>`).
  - `PUT /sessions/:id/board`: Saves evidence board layout and links.
  - `GET /daily`: Public endpoint returning today's UTC case only.
- Strict IDOR prevention: User B accessing User A's session returns 404 (not 403 to prevent enumeration).
- Two `Repository` implementations:
  - `PostgresRepository` (`@supabase/supabase-js`, with every user query explicitly scoped to authenticated `user_id`).
  - `InMemoryRepository` (for high-speed, Docker-free testing).
- Bundled the case engine with esbuild into `supabase/functions/_shared/engine.js` via `pnpm build:engine` (gitignored).
- Tested via Node Vitest using `app.request()` with deep leak scan on every response body: zero leaks.

  - `POST /sessions`: 201 Created with `{ session, case }`.
